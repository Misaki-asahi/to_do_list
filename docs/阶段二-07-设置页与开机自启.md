## 一、设计思路

### 1.1 开机自启：三种方案，为什么选"启动文件夹"

| 方案 | 需要管理员权限 | 用户能不能自己发现和删除 | 结论 |
| --- | --- | --- | --- |
| 注册表 `HKCU\...\Run` | 不需要 | ❌ 藏在注册表里，用户根本找不到 | 不选 |
| Windows 任务计划程序 | 部分操作需要 | 一般 | 过度复杂 |
| **启动文件夹** | **不需要** | ✅ 打开文件夹就能看见、能删 | ✅ **选它** |

启动文件夹的路径是：

    %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup

也就是：`C:\Users\你的名字\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup`

**放在这里的程序，用户登录后会被系统自动运行。** 就这么简单，不需要任何权限。

> **设计原则：越透明的机制越好。**
> 用户能在资源管理器里亲眼看到那个文件、亲手把它删掉，
> 比你写一百行"如何卸载自启"的说明文档都有用。

### 1.2 为什么放 `.vbs` 而不是 `.bat`？

| 文件类型 | 被系统启动时的表现 |
| --- | --- |
| `.bat` | **弹出一个黑色命令行窗口**，停在桌面上 |
| `.vbs` | 可以用 `WScript.Shell.Run` 的窗口样式参数（0 = 隐藏），**窗口完全不出现** |

所以自启用的是 `.vbs`。用户会以为"什么都没发生"，实际上服务已经在后台跑起来了。

### 1.3 一个必须说清楚的限制

**开机自启保证了「服务」在跑，但提醒弹窗需要「浏览器页面开着」。**

为什么？因为本项目的提醒是"前端轮询"驱动的（功能 9 讲的）。
没有页面在轮询，就没人去取提醒 ——

> 好消息是：**没被取走的提醒永远不会被消费掉**。
> 所以你下次打开页面时，**所有错过的提醒会立刻补弹**，一条都不会丢。

这个限制我没有藏起来，而是**直接写在设置页界面上**（那个黄色提示框）。
**把限制说清楚，比让用户自己撞上去要好得多。**

### 1.4 安全设计：目录白名单（防路径穿越）

"打开目录"这个功能接收一个 `target` 参数：

    POST /api/settings/open-folder  {"target": "data"}

如果不做限制，别人就能传 `../../windows` 或 `C:/Windows`，
让服务器（也就是你的电脑）在资源管理器里打开系统任意位置。这叫**路径穿越攻击**（Path Traversal）。

本项目的做法是**白名单**：

    FOLDER_MAP = {
        "project": lambda: config.BASE_DIR,
        "data":    lambda: config.DATA_DIR,
        "docs":    lambda: config.BASE_DIR / "docs",
        "exports": lambda: config.EXPORT_DIR,
        "startup": lambda: autostart.startup_dir(),
    }

**只有这几个值能被打开**，其余一律拒绝。

> 前面删任务时用的是"字段白名单"，这里用的是"路径白名单" ——
> **同一个思路，能防住一大类安全问题。**
> 记住这句话：**黑名单永远列不全，白名单天然安全。**

### 1.5 设置页的四个板块

| 板块 | 内容 |
| --- | --- |
| **开机自启** | 开关、启动时是否开浏览器、脚本路径、打开启动文件夹、**限制说明** |
| **数据** | 待办统计、数据库大小与路径、打开数据/项目/文档目录 |
| **提醒** | 检查间隔、稍后时长、单次上限、已开启的提醒数 |
| **关于** | 名称、版本、Python 版本、系统、服务地址、当前时间、接口文档入口 |

    def startup_dir() -> Path:
        appdata = os.environ.get("APPDATA")
        return Path(appdata) / "Microsoft" / "Windows" / "Start Menu" / "Programs" / "Startup"

    def _launcher_content(project_dir, open_browser):
        lines = [
            "' Offline Todo List - auto start launcher.",
            "' DELETE THIS FILE to disable auto start.",
            "Option Explicit",
            "Dim shell, fso, projectDir",
            "Set shell = CreateObject(\"WScript.Shell\")",
            "Set fso = CreateObject(\"Scripting.FileSystemObject\")",

            "shell.CurrentDirectory = projectDir",

        return "\r\n".join(lines) + "\r\n"

## 三、关键代码逐行解释

### 3.1 `.vbs` 里的引号地狱：`""` 是什么

VBScript 里，字符串用双引号包裹；如果字符串**内部**要有双引号，就写两个：

    "cmd /c """ & projectDir & "\start_silent.bat"""
         ↑↑                              ↑↑
      这里两个 "" = 一个 "

拆开看就很清楚了：

| 片段 | 含义 |
| --- | --- |
| `"cmd /c "` | 字符串 `cmd /c ` |
| `""` | 字符串里一个 `"` 字符 |
| `& projectDir &` | 拼接变量 |
| `"\start_silent.bat"` | 字符串 `\start_silent.bat` |
| `""` | 再一个 `"` 字符 |

拼出来就是：`cmd /c "E:\...\to_do_list\start_silent.bat"` —— 正好是我们要的。

> **为什么要这么绕？** 因为路径里可能有空格（比如 `C:\Program Files\...`），
> 不加引号的话命令行会把它拆成两段。**凡是往命令行里拼路径，都要加引号。**

### 3.2 `WScript.Shell.Run` 的第二个参数：`0` 表示隐藏窗口

    shell.Run "命令", 0, False
                     │  └── False = 不等待命令结束（异步启动）
                     └───── 0 = 窗口隐藏（1 = 正常显示，3 = 最大化）

如果写成 `1`，开机时你会看到一个黑窗口停在桌面上 —— 那就是"自启失败"的观感。
写成 `0` 才是真正的"静默启动"。

`False` 也很重要：表示**不等待**。否则 `.vbs` 会一直挂着等那个批处理结束
（而批处理跑的是一个永不退出的服务）。

### 3.3 自启脚本里的"自我检查"

    If Not fso.FileExists(projectDir & "\run.py") Then WScript.Quit 1

**为什么要有这一行？** 考虑这个场景：

1. 你开启了开机自启；
2. 后来把项目文件夹**移动**了或者**删掉**了；
3. 每次开机，这个 `.vbs` 都会尝试运行一个不存在的批处理。

结果是：**每次开机都弹一个错误对话框**，而你又不知道为什么。

加上这一行之后，如果 `run.py` 不存在，脚本**安静地退出**，什么都不做。

> **好的自启脚本，要在"目标已经消失"时安静地失败，而不是骚扰用户。**

### 3.4 `run.py --no-browser`：一行参数解决一个体验问题

    import sys
    no_browser = "--no-browser" in sys.argv
    ...
    if config.HOST in ("127.0.0.1", "localhost") and not no_browser:
        open_browser_later(url)
    elif no_browser:
        print("  （静默模式：请在浏览器里手动访问上面的地址）")

**为什么要这个参数？** 因为开机自启时如果每次都自动弹出浏览器，会很烦人 ——
你开机是要干活的，不想一上来就被一个网页挡住。

`sys.argv` 是 Python 的"命令行参数列表"，`xxx in sys.argv` 就是"用户有没有加这个参数"。
**这是最简单的命令行开关实现方式**，不需要任何第三方库。

### 3.5 `PYTHONUNBUFFERED=1`（本步踩的坑，见 BUG-010）

验证开机自启脚本时发现：**输出重定向到文件后，启动横幅不见了。**

原因是 Python 的输出缓冲机制：

| 输出去哪 | 缓冲方式 | `print()` 何时可见 |
| --- | --- | --- |
| 终端 / 控制台 | 行缓冲 | 立刻 |
| **文件 / 管道** | **块缓冲（约 8KB）** | **攒够了才写** |

我们的横幅只有几百字节，一直躺在缓冲区里没被写出来。
加一行 `set PYTHONUNBUFFERED=1` 就解决了（等价于 `python -u`）。

**详细分析见《问题记录与解决方案》BUG-010。**

### 3.6 CSS 开关：为什么要"藏起"真的 checkbox

    .switch input { position: absolute; opacity: 0; width: 0; height: 0; }

**为什么不直接删掉它，自己用 div 做一个开关？**

因为真正的 `<input type="checkbox">` 自带这些能力：

| 能力 | 自己用 div 做 | 用真 checkbox |
| --- | --- | --- |
| 键盘 Tab 聚焦 | 要自己加 `tabindex` | 自带 ✅ |
| 空格键切换 | 要自己监听键盘 | 自带 ✅ |
| 屏幕阅读器能读 | 要加一堆 ARIA 属性 | 自带 ✅ |
| `:checked` 伪类 | 做不到 | 自带 ✅ |

所以标准做法是：**保留真的 checkbox，用 CSS 把它隐藏，用它的"兄弟元素"来画外观。**

    .switch input:checked + .switch-track { background: var(--ok); }

`+` 是"相邻兄弟选择器"：选中"紧跟在被勾选的 input 后面的那个 track"。
**用户点的是好看的开关，实际改变的是那个看不见的 checkbox。**

> 这叫"**渐进增强**"：先保证功能可用（真 checkbox），再让它好看。
> 就算 CSS 挂了，功能依然能用。

## 四、如何运行

### 4.1 打开设置页

启动程序后：

- 点顶部导航的"**设置**"
- 或直接访问 `http://127.0.0.1:8000/settings`

### 4.2 开启开机自启

1. 打开"**开机自动启动**"开关 → 提示"已开启开机自启"
2. 路径框里会显示启动脚本的位置
3. 点"**打开启动文件夹**"，你能**亲眼看到**那个 `OfflineTodoList.vbs` 文件

> 💡 **想验证效果？** 不用真的重启电脑：**直接双击启动文件夹里那个 .vbs**，
> 服务就会像开机时那样在后台启动（不会弹黑窗口）。

### 4.3 "启动时同时打开浏览器"这个选项怎么选

| 你的使用习惯 | 建议 |
| --- | --- |
| 想让待办和提醒一直在手边 | **打开它** —— 开机自动开页面，提醒能弹出来 |
| 不想每次开机被网页挡住 | **关掉它**（默认）—— 后台静默运行，想用时自己开 |

## 六、常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 开关打不开 / 一直转圈 | 写入启动文件夹失败（权限、杀毒软件拦截） | 看开关旁边的红字提示；也可手动把 `.vbs` 放进启动文件夹 |
| 开关打开后又自动弹回去 | 后端写入失败，前端把开关恢复了真实状态 | 这是**正确行为**（界面不能和实际不一致）；看提示信息 |
| 开机后服务没起来 | ① Python 不在 PATH；② 项目文件夹被移动了 | 手动双击启动文件夹里的 `.vbs` 看有没有动静；确认路径没变 |
| 开机后服务起来了，但没有提醒 | **提醒需要浏览器页面开着** | 见 1.3；开启"启动时打开浏览器"选项 |
| 点"打开数据目录"没反应 | 系统不支持（非 Windows）或路径不存在 | `setting_service.open_folder` 会自动创建目录；其他系统用 `open`/`xdg-open` |
| 设置页数字不对 | 统计口径问题 | 对照待办页的统计；两处应该完全一致 |
| 启动时**看不到**命令行输出 | Python 输出缓冲（BUG-010） | 已有 `PYTHONUNBUFFERED=1`；若是自己写脚本，用 `python -u` |
