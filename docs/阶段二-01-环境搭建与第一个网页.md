# 第二阶段 · 功能 1：环境搭建与第一个网页

> 阶段：第二阶段（逐个功能实现）
> 本步目标：**不写任何待办功能**，先把"Python 服务 → 浏览器 → 前端 JS → 后端 API"这条链路彻底跑通。
> 完成标志：打开 http://127.0.0.1:8000 ，页面上三个圆点全是绿色。

---

## 一、设计思路（先讲清楚"为什么"，再看代码）

### 1.1 为什么第一步不做"添加待办"，而是先搭空架子？

新手最容易犯的错误是：**一上来就写最核心的功能**。结果一运行报错，你根本不知道是
Python 环境的问题、Web 服务器的问题、数据库的问题，还是前端代码的问题——四种可能混在一起，无从下手。

所以专业做法是**从外往里搭，一次只加一层，每加一层就验证一次**：

| 顺序 | 加什么 | 验证什么 | 出错了只可能是 |
| --- | --- | --- | --- |
| 第 1 步（本步） | 空服务 + 一个自检页 | 浏览器能打开、能调通接口 | 环境问题 |
| 第 2 步 | SQLite 数据库 | 数据能存能取 | 数据问题 |
| 第 3 步 | 添加待办 | 完整业务链路 | 业务逻辑问题 |

**每一步都建立在"上一步已经被证明是正确的"基础上**，这样出错时排查范围永远很小。
这就是为什么本步的内容看起来"没什么功能"，却必须单独占一步。

### 1.2 为什么把 HTML 和 CSS 放在独立文件里，而不是塞进 Python 字符串？

初学者版本常常这么写：

    return "<html><body><h1>待办</h1>...一大堆 HTML...</body></html>"

这样做的后果：Python 文件被 HTML 撑到几千行、编辑器没有语法高亮、改一个标点要翻半天、
想请别人帮你看前端还得解释 Python。**分层的第一原则就是：不同语言不混在一个文件里。**

所以本项目的路径约定是：

- `app/templates/*.html` —— 页面骨架
- `app/static/css/*.css` —— 样式
- `app/static/js/*.js` —— 交互逻辑
- `app/*.py` —— 后端

### 1.3 为什么前端要专门有一个 api.js？

如果让每个页面自己写 `fetch('/api/tasks')`，会造成三个后果：

1. 以后后端地址变了（比如部署成公网网址），要改十几个地方，改漏一个就出鬼；
2. `fetch` 有一个著名的坑（下一节会讲），每个人写的处理方式还不一样；
3. 出问题时不知道是哪个页面写错了。

**api.js 是前端与后端之间的唯一通道**。所有请求都从它走，改地址只改一行常量。
这是"给未来的自己省事"的典型做法，第三阶段重构时你会感谢现在的自己。

### 2.2 `app/main.py`（装配中心）

    # -*- coding: utf-8 -*-
    """main.py -- 应用装配中心。只做装配，不写业务逻辑。"""

    from fastapi import FastAPI
    from fastapi.responses import FileResponse
    from fastapi.staticfiles import StaticFiles

    from app import config

    app = FastAPI(
        title=config.APP_NAME,
        version=config.APP_VERSION,
        description="离线待办清单的本地接口。打开 /docs 可以直接调试每一个接口。",
    )

    # 把 static 文件夹暴露到网址 /static 下面
    app.mount("/static", StaticFiles(directory=str(config.STATIC_DIR)), name="static")


    def _page(filename: str) -> FileResponse:
        """返回 templates 目录下的某个 HTML 页面。"""
        return FileResponse(config.TEMPLATE_DIR / filename, media_type="text/html")


    @app.get("/", include_in_schema=False)
    def page_todo_list():
        return _page("index.html")


    @app.get("/calendar", include_in_schema=False)
    def page_calendar():
        return _page("calendar.html")


    @app.get("/settings", include_in_schema=False)
    def page_settings():
        return _page("settings.html")


    @app.get("/api/health", tags=["系统"], summary="健康检查")
    def health():
        return {
            "status": "ok",
            "app": config.APP_NAME,
            "version": config.APP_VERSION,
            "db_path": str(config.DB_PATH),
        }

### 2.3 `run.py`（总入口）

    # -*- coding: utf-8 -*-
    """run.py -- 项目总入口：python run.py 启动服务并自动打开浏览器。"""

    import threading
    import time
    import webbrowser

    import uvicorn

    from app import config


    def open_browser_later(url, delay=1.5):
        """延迟一点再打开浏览器，避免用户先看到一个"无法连接"的页面。"""
        def _open():
            time.sleep(delay)
            webbrowser.open(url)

        threading.Thread(target=_open, daemon=True).start()


    def main():
        config.ensure_dirs()
        url = "http://%s:%d" % (config.HOST, config.PORT)

        print("=" * 56)
        print("  %s  v%s" % (config.APP_NAME, config.APP_VERSION))
        print("=" * 56)
        print("  主界面  : %s" % url)
        print("  接口文档: %s/docs" % url)
        print("  数据文件: %s" % config.DB_PATH)
        print("  按 Ctrl + C 停止服务")
        print("=" * 56)

        if config.HOST in ("127.0.0.1", "localhost"):
            open_browser_later(url)

        uvicorn.run("app.main:app", host=config.HOST, port=config.PORT, reload=False)


    if __name__ == "__main__":
        main()

### 2.4 `app/static/js/api.js`（前端唯一出口）

    // api.js -- 前端与后端通信的唯一出口
    // 现在前后端同地址，所以留空；将来部署到别处只改这一行。
    const API_BASE = '';

    async function request(path, options) {
      options = options || {};

      const response = await fetch(API_BASE + path, {
        method: options.method || 'GET',
        headers: { 'Content-Type': 'application/json' },
        body: options.body ? JSON.stringify(options.body) : undefined,
      });

      // fetch 的坑：服务器返回 404/500 时它【不会】抛异常，必须自己检查
      if (!response.ok) {
        const text = await response.text().catch(function () { return ''; });
        throw new Error('请求失败 ' + response.status + ' ' + path + ' ' + text);
      }

      if (response.status === 204) return null;   // 204 = 成功但没有内容（如删除）
      return await response.json();
    }

    // 所有接口集中登记在这里
    const api = {
      health: function () { return request('/api/health'); },
    };

    window.api = api;
    // "信号灯"：只要能执行到这一行，就说明 api.js 加载成功了
    window.APP_STATIC_READY = true;

### 2.8 `start.bat`（Windows 一键启动）

> ⚠️ **这个文件有两条铁律，违反任何一条都会导致"双击窗口一闪而过"**：
> ① 行尾必须是 **CRLF**（Windows 换行）；② 文件内容必须是**纯 ASCII**，不许出现中文。
> 详细原因见本文档第七章「Bug 实录 1」。

    @echo off
    chcp 65001 >nul
    cd /d "%~dp0"

    rem ---- 强制 UTF-8，让 Python 打印的中文能正确显示 ----
    set PYTHONUTF8=1
    set PYTHONIOENCODING=utf-8

    rem ---- 找可用的 Python：优先 python，找不到就退回 py 启动器 ----
    set "PYBIN=python"
    where python >nul 2>nul || set "PYBIN=py"

    %PYBIN% --version >nul 2>nul
    if errorlevel 1 (
        echo.
        echo   [ERROR] Python was not found on this computer.
        echo   Please install Python 3.10 or newer from:
        echo       https://www.python.org/downloads/
        echo   During setup, tick "Add python.exe to PATH".
        echo.
        pause
        exit /b 1
    )

    if not exist "run.py" (
        echo.
        echo   [ERROR] run.py was not found next to start.bat.
        echo   Please keep start.bat inside the project root folder.
        echo.
        pause
        exit /b 1
    )

    echo.
    echo   Starting Offline Todo List ...
    echo.

    %PYBIN% run.py

    echo.
    echo   Server stopped. Press any key to close this window.
    pause >nul

## 三、关键代码逐行解释

### 3.1 `BASE_DIR = Path(__file__).resolve().parent.parent`

这是整个项目**最重要的一行**，因为它决定了"程序去哪里找数据"。

| 片段 | 含义 | 结果示例 |
| --- | --- | --- |
| `__file__` | 当前这个 .py 文件的位置 | `app/config.py` |
| `.resolve()` | 转成绝对路径 | `E:\...\to_do_list\app\config.py` |
| `.parent` | 上一级目录 | `E:\...\to_do_list\app` |
| `.parent.parent` | 再上一级 | `E:\...\to_do_list` ← 项目根 |

**为什么不能直接写死 `"E:/我的项目/data"`？**
因为以后你把项目发到 GitHub，别人下载到的是 `D:\下载\to_do_list`，路径不一样，
程序会直接找不到文件而崩溃。用 `__file__` 推导出来的路径**永远相对于项目自己**，
不管项目放在哪儿都能正确工作。

### 3.2 `app.mount("/static", StaticFiles(directory=...), name="static")`

这行的意思是：**把本地磁盘上的一个文件夹，挂到网址的一个前缀下面**。

    app/static/css/style.css   ──挂载后──>   http://127.0.0.1:8000/static/css/style.css

- 第一个参数 `"/static"` 是网址前缀；
- `StaticFiles(directory=...)` 告诉 FastAPI 这个前缀对应磁盘上的哪个文件夹；
- `name="static"` 是给这个挂载点起的内部名字，FastAPI 用它反向生成网址（现在用不到，但必须给）。

**为什么要 `str()` 转换？** 因为 `config.STATIC_DIR` 是 `Path` 对象，
而 StaticFiles 只接受字符串。这是 Python 里类型要求严格的地方。

### 3.3 路由装饰器 `@app.get("/api/health")`

    @app.get("/api/health", tags=["系统"], summary="健康检查")
    def health():
        return {...}

- `@app.get(...)` 是一个**装饰器**：它把下面这个普通函数"登记"到网址表里。
  意思是"当有人用 GET 方法访问 /api/health 时，就调用 health 函数"。
- **返回值就是响应内容**：返回 dict，FastAPI 会自动把它转成 JSON 发出去。
  你不需要自己写 `json.dumps()`，也不需要设置 `Content-Type`。
- `tags` 和 `summary` 只影响 `/docs` 文档页的显示，纯粹为了方便，不影响功能。
- `include_in_schema=False`（用在页面路由上）表示"这条不要出现在接口文档里"——
  因为页面是给人看的，不是给程序调的。

### 3.4 `async function` + `await fetch`：前端异步的坑

    const response = await fetch('/api/health');
    if (!response.ok) { throw new Error(...); }
    const data = await response.json();

三行代码，三个必须理解的要点：

1. **`await` 是"等它做完再往下走"**。网络请求需要时间（可能几毫秒也可能几秒），
   不加 `await` 会拿到一个还没完成的结果（一个 Promise 对象），后面全乱套。
   只有 `async` 函数内部才能使用 `await`。

2. **`fetch` 不会因为 404、500 而报错！** 这是 JavaScript 里最坑的设计之一。
   服务器返回"找不到页面"，`fetch` 也认为"请求成功完成了"。
   所以**必须手动检查 `response.ok`**（它在状态码 200~299 时为 true）。
   如果漏了这一步，程序出错时你会看到"数据是 undefined"，而完全不知道真正原因是 404。

3. **`.json()` 也要 `await`**。因为读取响应体同样是异步的。
   漏掉 `await` 会得到一个 Promise 而不是数据，页面显示 `[object Promise]`。

### 3.5 `threading.Thread(target=_open, daemon=True).start()`

    def open_browser_later(url, delay=1.5):
        def _open():
            time.sleep(delay)
            webbrowser.open(url)
        threading.Thread(target=_open, daemon=True).start()

- `target=_open` 是"这个线程要去执行哪个函数"（注意：**不加括号**，
  加括号会立刻执行，那就没有开线程的意义了）。
- `.start()` 才是真正启动线程。
- `daemon=True` 意思是"守护线程"：主程序结束时它跟着结束。
  **如果不写 daemon=True，主程序退出时会卡住等它**——因为 Python 默认要等所有线程结束。
- **为什么需要线程？** 因为 `time.sleep` 会阻塞。如果直接在主线程里 sleep，
  服务器启动就会被推迟 1.5 秒。

### 3.6 IIFE：`(function () { ... })();`

外面这层括号的作用是**制造一个私有的作用域**。

不用它的话，`health.js` 里的 `check`、`output` 等变量会跑到全局，
以后 `list.js` 里再定义一个 `check`，两个文件就会互相覆盖，出现"莫名其妙就不对了"的 bug。
用 IIFE 包起来，变量就只在这个文件内部可见——**每个文件一个独立小房间**。

### 3.7 `uvicorn.run("app.main:app", ...)` 这个字符串是什么意思

- `app.main` —— 相当于"去 `app/main.py` 这个文件"；
- `:` —— "里面的"；
- `app` —— "那个叫 `app` 的变量"。

合起来就是"找到 app/main.py 里那个叫 app 的 FastAPI 对象"。
用字符串而不是直接 `import` 传对象，是为了支持之后开启自动重载（`reload=True`）功能。

    python scripts/smoke_test.py

### 测试 4（教你排查问题的思维）：故意制造一个错误

**目的**：让你亲眼看到"错误长什么样"，以后真出错时就不慌了。

1. 打开 `app/static/js/api.js`；
2. 把 `health: function () { return request('/api/health'); }` 改成
   `return request('/api/health-typo');`（故意写错路径）；
3. 保存，回到浏览器按 `F5` 刷新；
4. 观察结果：
   - 前两个点还是绿色（静态资源、后端服务都正常）；
   - 第三个点变红（接口调用失败）；
   - 黑框里显示 `检测失败：请求失败 404 ...`。

**这次实验教会你一件重要的事**：红点出现的位置**精确定位了故障在哪一层**。
这正是我们做这个自检页的价值——不需要猜。
（测完记得把路径改回来。）

### 测试 5：打开浏览器开发者工具

按 **F12** → 切到 "Console"（控制台）标签。
以后页面有任何 JS 问题，第一个要看的就是这里，红色字就是错误信息。
再切到 "Network"（网络）标签并刷新页面，你能看到每一个请求的网址、状态码、耗时——
排查"接口没反应"这类问题时，这里比任何地方都直观。

## 六、常见 Bug 排查（现象 → 原因 → 解决）

| 现象 | 根本原因 | 解决办法 |
| --- | --- | --- |
| 双击 start.bat 后窗口一闪而过 | `python` 不在系统 PATH 里 | 用命令行运行 `python run.py` 看完整报错；或重新安装 Python 时勾选 "Add Python to PATH" |
| 提示 `ModuleNotFoundError: No module named 'fastapi'` | 依赖没装 | `pip install -r requirements.txt` |
| 提示 `ModuleNotFoundError: No module named 'app'` | 没在项目根目录运行 | `cd` 到 `to_do_list` 目录（`start.bat` 里的 `cd /d "%~dp0"` 就是干这个的） |
| `[Errno 10048] address already in use` | 8000 端口被占用（多半是上一个窗口没关） | 关掉旧窗口；或换端口：`set TODO_PORT=8010` 后再运行 |
| 浏览器显示"无法访问此网站" | 服务没启动，或用的网址端口不对 | 看黑窗口打印的地址，必须和地址栏完全一致 |
| 页面能打开但**没有样式**（纯白底黑字） | CSS 路径不对 | 按 F12 看 Network 里 `style.css` 是不是 404；确认 HTML 里写的是 `/static/css/style.css` |
| 三个点全红，黑框显示"检测失败" | 后端没起来 / 端口不对 | 先在浏览器直接访问 `http://127.0.0.1:8000/api/health`，能看到 JSON 就说明后端没问题，那就是前端问题 |
| Ctrl+C 关不掉服务 | 有子进程残留 | 关掉整个终端窗口；或在任务管理器里结束 python.exe |
| 中文显示成乱码（命令行里） | 终端编码不是 UTF-8 | `start.bat` 里的 `chcp 65001` 已经处理了；命令行手动运行时执行一次 `chcp 65001` |
| **双击 start.bat 窗口一闪而过** | **① .bat 行尾是 LF 而不是 CRLF；② .bat 里写了中文** | **见第七章「Bug 实录 1」——这是本项目实际踩过的坑** |

### 排查心法（比记住表格更重要）

遇到问题时，**永远按这个顺序从外往里查**：

1. **后端活着吗？** → 浏览器直接访问 `/api/health`。能看到 JSON，后端就是好的。
2. **静态文件能加载吗？** → 浏览器直接访问 `/static/js/api.js`。能看到 JS 源码，路径就是对的。
3. **前端报错了吗？** → F12 看 Console 的红色错误。
4. **请求发出去了吗？** → F12 看 Network 的请求和状态码。

这四步能解决 90% 的问题。顺序反了（一上来就盯着 Python 代码改）会让你浪费大量时间。

## 七、Bug 实录：双击 start.bat 窗口一闪而过（已修复）

> **完整的七段式记录（症状 / 复现 / 报错 / 根因 / 修复 / 验证 / 经验）已归档到
> 《问题记录与解决方案》文档的 BUG-001。**
> 那个文档是本项目**所有踩坑的统一入口**，以后每遇到一个问题都会往里追加一条。
> 本节只保留最关键结论，方便你在本步骤内快速回顾。

### 7.1 症状

双击 `start.bat`，黑窗口闪一下就消失，什么提示都来不及看清。

### 7.2 根因（两个原因叠加）

| # | 原因 | 说明 |
| --- | --- | --- |
| 1 | **行尾是 LF 而不是 CRLF**（致命） | `cmd.exe` 按字节偏移量解析批处理文件，默认行尾为 CRLF；遇到 LF 会"读串位"，把 `echo` 吃掉，剩下的中文被当成命令去执行 |
| 2 | **`.bat` 文件里写了中文**（加重） | 命令行代码页是 936(GBK)，文件是 UTF-8，汉字字节被误读成 `??动`，进一步加剧错位 |

> 关键区别：Python / HTML / JS 用 LF 完全没事，因为它们**读完整个文件再解析**。
> 只有 `.bat` / `.cmd` / `.vbs` 这类老式批处理对行尾极度敏感。

### 7.3 修复方案

- 行尾转成 **CRLF**（实测结果：42 个 CRLF、**0 个孤立 LF**）
- `.bat` 内容改为**纯 ASCII**，所有中文提示交给 Python 打印
- 每个错误分支加 `pause`，让窗口停住不自动关闭
- 启动前检测 `python`，找不到就退回 `py` 启动器，都没有则给出人话提示
- 加 `set PYTHONUTF8=1` + `set PYTHONIOENCODING=utf-8`，配合 `chcp 65001` 保证中文不乱码

### 7.4 验证

① 字节检查三项达标（CRLF=42 / 孤立LF=0 / 非ASCII=0）；
② 用**同一条**复现命令 `cmd /c "start.bat > _out.txt 2>&1"` 再跑一次，输出正常；
③ `http://127.0.0.1:8000/api/health` 返回 **200**。

### 7.5 一句话经验

> **`.bat` 文件：行尾必须 CRLF，内容必须纯 ASCII，结尾必须有 `pause`。**

完整分析过程见《问题记录与解决方案》**BUG-001**。
