## 一、设计思路

### 1.1 关键决策：日期网格计算放在后端

"这个月 1 号是星期几""要不要补格子""跨年怎么办""闰年二月有几天" ——
这些边界情况**在前端写很容易出错**，而 Python 的 `datetime` / `calendar` 处理它们是强项。

所以本项目的分工是：

| 层 | 负责 |
| --- | --- |
| **后端 `calendar_service.py`** | 算出完整的网格（每周一行、每行 7 格），已经排好版 |
| **前端 `calendar.js`** | 把二维数组画出来 + 处理点击 |

前端拿到的 `weeks` 是**可以直接 `map` 渲染的二维数组**，一行日期计算都不用写。

### 1.2 网格是怎么算出来的（四步）

```
① 本月第一天 = date(2026, 9, 1)

② 本月最后一天：calendar.monthrange(2026, 9) -> (1, 30)
                                         ↑这个月1号是星期几  ↑这个月有30天
   所以最后一天 = date(2026, 9, 30)

③ 补齐成完整周（Python 里 weekday()：周一=0，周日=6）
   往左补：1号是周二（weekday=1）-> 往前退 1 天到周一 -> 网格从 8月31日 开始
   往右补：30号是周三（weekday=2）-> 往后加 4 天到周日 -> 网格到 10月4日 结束

④ 从网格起点开始，每 7 天切一行，得到：
   [8/31, 9/1, 9/2, 9/3, 9/4, 9/5, 9/6]
   [9/7,  9/8, 9/9, 9/10, 9/11, 9/12, 9/13]
   ...
```

> **这个"补两头凑整周"的思路，是所有日历控件的通用算法。**
> 记住它，以后写任何日历（哪怕换成 Vue/React）都是同一套。

### 1.3 日历上放哪个日期？

用 **`due_at`（截止/计划日期）**，不是 `remind_at`。

| 字段 | 含义 | 该不该上日历 |
| --- | --- | --- |
| `due_at` | 这件事属于哪天 | ✅ 是 |
| `remind_at` | 什么时候叫我 | ❌ 不是 |

**没有 `due_at` 的任务不会出现在月历上** —— 所以页面专门给它们一个"未安排日期"面板，
否则这些任务就"消失"了（用户会以为数据丢了）。

### 1.4 只填日期不填时间时，默认 23:59

用户点 9 月 20 日、输入"交作业"、不填时间 —— 意思是"这件事属于这天"。
用 `23:59` 表示"**当天结束前**"，这是通用约定（Google Tasks 也是类似做法）。

### 1.5 一个容易忽略的点：过去的日期不能新建

后端本来就有规则"截止时间不能早于当前时间"，所以点过去的日子新建会被 400 拦下。
但**光靠后端报错体验很差** —— 用户点一下、填一堆字、点添加，才被告知"不行"。

所以前端提前把过去日期的输入框**禁用掉**，并直接显示原因：

    if (info.is_past) {
      qTitle.disabled = true;
      qTime.disabled = true;
      qSubmit.disabled = true;
      showMsg(qMsg, "过去的日子不能新建待办", true);
    }

> **通用原则：能把错误"提前拦住"的，就不要留到提交后再报。**
> 后端校验是**安全底线**（必须保留），前端禁用是**体验优化**（两者都要）。

    def list_between(start_text, end_text, user_id=1):

        stmt = select(Task).where(

**为什么可以直接用字符串比较大小？** 因为决策 3B 把时间存成了 `YYYY-MM-DD HH:MM`，
从大到小排列，**字符串比较的顺序恰好就是时间顺序**：

## 三、关键代码逐行解释

### 3.1 `first_day.weekday()`：Python 的星期是从 0 开始的

| `weekday()` 返回值 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 对应星期 | **一** | 二 | 三 | 四 | 五 | 六 | **日** |

所以"往前退到周一"就是 `- timedelta(days=first_day.weekday())`；
"往后推到周日"就是 `+ timedelta(days=6 - last_day.weekday())`。

> ⚠️ **易混淆点**：JavaScript 的 `Date.getDay()` 是**周日 = 0**，和 Python 正好差一天！
> 跨语言写日期时这是经典坑。本项目把计算都放在 Python 里，就避开了这个问题。

### 3.2 `calendar.monthrange(year, month)` 返回什么

    calendar.monthrange(2026, 9)  ->  (1, 30)
                                       │   │
                                       │   └─ 这个月有 30 天
                                       └───── 这个月 1 号是周二（1）

**它的第一个返回值就是我们需要的"1 号是星期几"**，不用自己算。
而且它自动处理闰年：

    calendar.monthrange(2024, 2)  ->  (3, 29)   # 闰年 29 天
    calendar.monthrange(2025, 2)  ->  (5, 28)   # 平年 28 天

### 3.3 `setdefault`：分组统计的惯用写法

    by_date = {}
    for task in tasks:
        key = task.due_at[:10]              # "2026-09-20 08:30" -> "2026-09-20"
        by_date.setdefault(key, []).append(task.to_dict())

`dict.setdefault(key, 默认值)` 的意思是：

- 如果 `key` 不存在 → 先把它设成默认值，然后返回这个默认值；
- 如果 `key` 已存在 → 直接返回现有的值。

所以这一行等价于：

    if key not in by_date:
        by_date[key] = []
    by_date[key].append(...)

**四个字变成一行**，而且不会漏掉任何一次分组的初始化。

### 3.4 `cell.tasks.slice(0, 3)`：格子里不能塞太多

一个日期格子空间有限。如果那天有 10 条待办，全塞进去会把整个日历撑变形。

    const shown = cell.tasks.slice(0, 3);       // 只取前 3 条
    const more = cell.tasks.length > 3
      ? "<div class=\"cal-more\">+" + (cell.tasks.length - 3) + " 条</div>"
      : "";

**注意 `slice` 不会修改原数组**（它返回一个新数组）——
和会修改原数组的 `splice` 完全不同，这两个名字很像，考试和实战都爱考。

### 3.5 ★ 参数容错与 BUG-009

这一步踩了一个很有价值的坑，完整记录在《问题记录与解决方案》**BUG-009**。

**简要版**：我最初把路由参数写成 `year: int`，想着"FastAPI 会帮我转成整数"。
结果 `?year=abc` 在**框架层**就被拦下返回 422 ——
**服务层里写的"退回今天"的容错代码，一行都没有机会执行。**

修复方式是把参数改用 `str` 接收，自己解析：

    def get_month(
        year: str = Query(None),     # ← 刻意用 str，不用 int
        month: str = Query(None),
    ):
        return calendar_service.month_view(year, month)

> **核心教训：校验发生的位置，决定了你的容错代码有没有机会运行。**
> 拦在前面的层，后面的层就永远看不到这个错误。

### 3.6 为什么日历页要"容错"而不是"报错"

| 场景 | 该怎么做 |
| --- | --- |
| 给**程序**调用的 API | 参数格式不对就返回 422 —— 这样调用方能立刻发现自己的 bug |
| 给**浏览器页面**用的接口 | 非法参数退回默认值 —— 用户手改网址、书签过期都不该白屏 |

**这不是"要不要严谨"的问题，而是"这个接口的调用者是谁"的问题。**
调用者是程序，就要严格；调用者是人，就要宽容。

## 四、如何运行

### 4.1 打开日历页

启动程序（双击 `start.bat`），然后：

- 点页面顶部导航的"**日历**"
- 或者直接访问 `http://127.0.0.1:8000/calendar`

### 4.2 界面说明

| 区域 | 说明 |
| --- | --- |
| 顶部 | `‹ 上月` / 月份标题 / `下月 ›` / `今天` 按钮 |
| 星期表头 | 一 二 三 四 五 六 日（**周一开头**） |
| 日期格子 | 每格显示日期数字 + 那天的待办（最多 3 条，超出显示"+N 条"） |
| 颜色含义 | **今天** = 蓝色边框；**非本月** = 灰底；**过去** = 淡色；**选中** = 蓝色高亮 |
| 选中某天 | 下面显示那天的待办 + 一个快速添加框 |
| 未安排日期 | 没有截止时间的待办（它们不会出现在月历上） |

### 4.3 添加一条带日期的任务

1. 点日历上的某一天（**未来**的日子）
2. 在"在这天添加一条待办…"里输入标题
3. 时间默认 `23:59`（表示"当天结束前"），想精确到几点就改掉
4. 点"添加"

**新任务立刻出现在那天的格子里。**

## 六、常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 日历是空的 / 一直"正在加载" | `/api/calendar/month` 报错 | F12 → Network 看这个请求的状态码；或直接浏览器打开该网址 |
| 任务不出现在日历上 | 那条任务**没有填截止时间** | 去待办页编辑它，填上截止时间；或在"未安排日期"面板里找它 |
| 日期格子里的任务显示不全 | 每格最多显示 3 条，超出显示"+N 条" | **这是设计如此**；点那天的格子看完整列表 |
| 点过去的日期没法输入 | 前端主动禁用了 | **设计如此**（见 1.5）；要补录过去的事，请用待办页 |
| 星期对不上（差一天） | Python 是周一=0，JS 是周日=0，容易混 | 本项目日期计算全在 Python 做；见 3.1 |
| 跨年时"上月/下月"出错 | 没处理 1 月的上月 = 去年 12 月 | 见 `calendar_service.py` 里的 prev/next 计算 |
| 手改网址后页面白屏 | 参数容错没生效（BUG-009） | 确认路由参数用的是 `str` 而不是 `int` |
