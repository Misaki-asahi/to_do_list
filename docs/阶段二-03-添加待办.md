## 一、设计思路

### 1.1 这是第一次"盖楼"

前两步都在打地基（环境、数据库）。这一步开始盖第一层楼，
也是**第一次把完整的三层架构串起来**。记住这条链路，以后每个功能都是它：

    前端表单
       ↓  fetch POST /api/tasks  {"title": "买牛奶"}
    路由层  routers/tasks.py      收请求、交给服务层
       ↓
    校验层  schemas.py            格式对不对？（不对 → 422）
       ↓
    服务层  services/task_service.py   业务上合不合理？（不合理 → 400）
       ↓
    数据层  repositories/task_repo.py  写进数据库
       ↓
    SQLite  data/todo.db
       ↓
    原路返回 JSON → 前端把新任务插进列表

### 1.2 为什么一定要分 schemas.py 和 models.py？

这是初学者最容易搞混、也最容易吃亏的地方。

| 文件 | 描述什么 | 用谁实现 |
| --- | --- | --- |
| `models.py` | **数据库表**长什么样 | SQLAlchemy |
| `schemas.py` | **接口收发**的 JSON 长什么样 | Pydantic |

**如果偷懒共用 models.Task 会怎样？** 用户提交时就可以这样写：

    POST /api/tasks
    {"id": 999, "created_at": "1999-01-01 00:00", "title": "随便写"}

结果：**主键被伪造、创建时间被篡改**，数据库彻底不可信。

分开之后，`TaskCreate` 里**根本没有** `id` 和 `created_at` 这两个字段，
用户想传也传不进来。这叫**从结构上杜绝**，比事后写检查代码可靠得多。

> 一句话记住：**能不能做**靠结构，**做了对不对**靠检查。能靠结构的，绝不用检查。

### 1.3 校验分两层，各管各的

| 层 | 管什么 | 出错返回 | 例子 |
| --- | --- | --- | --- |
| `schemas.py`（Pydantic） | **格式** | **422** | 标题太长、时间格式不对、优先级超范围 |
| `task_service.py`（服务层） | **业务** | **400** | 提醒时间早于现在、开了提醒却没填时间 |

**为什么分开？** 因为"格式错误"和"业务错误"要发给用户的信息完全不同。
格式错误是"你填的东西我读不懂"，业务错误是"我读懂了，但这样不合理"。

### 1.4 关于表单形态的一处调整

原设计文档写的是**弹窗式表单**，实现时改成了**内嵌式**（像 Google Tasks 那样）。

理由：待办是需要**高频、快速录入**的东西。弹窗每次都要"点开 → 填 → 关掉"，
多一次点击、多一次等待动画；内嵌式始终可见，填完即走，而且能连续录入。
**这是从实际使用手感出发做的取舍，不是偷懒。**

    class BusinessError(ValueError):
        """业务规则不通过时抛出的异常。"""
        pass


    def create_task(data):
        title = (data.title or "").strip()

        # 规则 1：填了提醒时间，就自动打开提醒开关
        remind_enabled = bool(data.remind_enabled or data.remind_at)

        # 规则 2：开了提醒就必须有提醒时间

        if data.priority not in config.PRIORITY_NAMES:
            raise BusinessError("优先级只能是 0（低）/ 1（中）/ 2（高）")

## 三、关键代码逐行解释

### 3.1 `Field(..., min_length=1, max_length=200)` —— 声明式校验

- **`...`（三个点）是 Python 的 Ellipsis**，在 Pydantic 里表示**这个字段必填**。
  不写它、写成 `None` 就表示可选。
- `min_length` / `max_length` / `ge`（≥）/ `le`（≤）这些叫**约束**，
  由 Pydantic 自动检查，你一行 if 都不用写。

**这种思路叫"声明式"**：你只描述"我希望它长什么样"，不描述"怎么检查"。
以后要改规则，改数字即可，不用动逻辑。

### 3.2 为什么 `min_length=1` 挡不住三个空格？

`"   "` 这个字符串**长度是 3**，完全满足 `min_length=1`，能顺利通过。
但它明显是"空的"。

所以必须自己写一个 `@field_validator`：

    value = (value or "").strip()
    if not value:
        raise ValueError("标题不能为空，也不能只有空格")

> **通用经验：长度校验挡不住"看起来有值其实是空白"的输入。**
> 凡是字符串必填项，都要额外做一次 `.strip()` 判空。

### 3.3 `@field_validator("due_at", "remind_at")` 为什么能一次管两个字段

装饰器里可以写多个字段名，表示"这两个字段都用下面这个函数校验"。
好处是**规则只写一遍**——以后格式要改，改一处两个字段同时生效。

函数里先把**空字符串转成 None**：

    if value is None or str(value).strip() == "":
        return None

**为什么？** 因为前端提交空输入框时给的是 `""`。
如果不管它，数据库里就会出现 `""` 和 `NULL` 两种"空"，
以后查询要写 `WHERE remind_at IS NULL OR remind_at = ''`，很容易漏。**统一成 None 就只有一个空。**

### 3.4 FastAPI 的 422 是怎么自动产生的

只要路由函数把 `TaskCreate` 写在参数上：

    def create_task(payload: TaskCreate):

FastAPI 就会自动：解析 JSON → 交给 Pydantic → 校验失败就返回 **422** 并附上详细原因。
**你一行校验代码都不用写**，而且返回格式在 `/docs` 里会自动生成文档。

### 3.5 `APIRouter(prefix="/api/tasks")` —— 别把网址写死在每个函数上

如果没有 prefix，每个接口都要写全路径：

    @router.post("/api/tasks")
    @router.get("/api/tasks")
    @router.get("/api/tasks/stats")

有了 prefix，函数里只写相对部分（`""`、`"/stats"`）。
**以后要把 API 整体迁到 `/v2/tasks`，只改一行。**

### 3.6 ⚠️ 路由顺序的坑：`/stats` 必须写在 `/{task_id}` 前面

FastAPI 是**按定义顺序**匹配路由的。
以后加"按 id 查询"接口 `@router.get("/{task_id}")` 时，
如果它写在 `/stats` **前面**，那么访问 `/api/tasks/stats` 时，
FastAPI 会先把 `"stats"` 当成 `task_id` 去匹配 → 结果是把 `"stats"` 转成整数失败，直接报错。

> 所以 `routers/tasks.py` 里的注释特意写了这一点。**静态路径永远放在动态路径前面。**

### 3.7 为什么业务错误返回 400，格式错误返回 422

| 状态码 | 含义 | 谁造成的 | 用户该怎么做 |
| --- | --- | --- | --- |
| **400** | 请求本身没毛病，但业务上不合理 | 用户的判断 | "哦，我提醒时间填早了，改一下" |
| **422** | 请求的数据格式我读不懂 | 用户的输入 | "哦，格式写错了" |
| **500** | **程序有 Bug** | **开发者** | 用户什么都做不了，只能报 bug |

**这条区分非常重要**：500 出现时应该去报警、去修代码；
400/422 出现时应该优化提示文案。混为一谈，就没法判断"是我的错还是用户的错"。

### 3.8 `event.preventDefault()` —— 不加这行，整套 JS 都白写

表单的**默认行为是提交后刷新整个页面**。
如果不阻止它，你辛苦写的：

    const created = await api.createTask(payload);
    await loadTasks();

会在执行到一半时**被页面刷新打断**，用户看到的是白屏闪一下，然后什么都没发生。

**`event.preventDefault()` 的作用就是"别刷新，我来处理"。**
这是所有前端表单处理的第一个必写动作。

### 3.9 `datetime-local` 的格式差异：字母 T ↔ 空格

`<input type="datetime-local">` 是浏览器原生控件，好处是自带日历弹窗、自动校验。
但它给出的值格式和我们的后端不一样：

| 来源 | 格式 |
| --- | --- |
| 浏览器控件给你的 | `2026-09-20T08:30` （中间是字母 **T**，ISO 8601 标准） |
| 我们后端要的 | `2026-09-20 08:30` （中间是**空格**） |

所以需要两个转换函数：

    toApiTime(value)   // "2026-09-20T08:30" -> "2026-09-20 08:30"   提交时用
    toInputTime(value) // "2026-09-20 08:30" -> "2026-09-20T08:30"   回填表单时用

`.slice(0, 16)` 是为了**统一截断到分钟**——有些浏览器会带上 `:00` 秒，
不截断的话就变成 `2026-09-20 08:30:00`，和数据库里其他数据的格式不一致，比较时会出错。

### 3.10 ★ `escapeHtml()` —— XSS 攻击防护（本步最重要的安全知识）

`list.js` 渲染列表时用了 `innerHTML`，因为它拼接起来最直观。
但 `innerHTML` 有一个**致命特性：它会把字符串当成真正的 HTML 来解析和执行。**

假设没有转义，用户把待办标题写成：

    <img src=x onerror="alert('你的数据被偷了')">

保存后，前端一渲染，浏览器看到 `<img>` 标签就会**真的去加载这张图**，
加载失败就**真的执行 `onerror` 里的 JavaScript**。

如果是真实攻击，这段脚本可以做到：

- 读取你页面上的一切内容
- 用你的身份去调用后端接口，**把你所有待办都删掉**
- 把数据偷偷发到攻击者的服务器

**这就是 XSS（跨站脚本攻击）。本项目以后要发布到公网，这一步绝不能省。**

转义的作用：把有特殊含义的字符换成"仅表示文字"的形式。

| 字符 | 转义成 | 效果 |
| --- | --- | --- |
| `<` | `&lt;` | 浏览器知道"这是一个小于号字符"，而不是标签开始 |
| `>` | `&gt;` | 同理 |
| `&` | `&amp;` | 必须**第一个**替换，否则会把后面刚转义出来的 `&` 又转一遍 |
| `"` `'` | `&quot;` `&#39;` | 防止跳出 HTML 属性 |

> **更彻底的方案**：用 `document.createElement` + `textContent` 创建元素，
> 这样根本没有 HTML 解析这一步，从原理上不可能被注入。
> 本步先用"转义 + innerHTML"，因为它更好读；第三阶段重构时可以考虑改成 DOM 方式。

### 3.11 `finally { btnSubmit.disabled = false; }` 为什么要用 finally

    btnSubmit.disabled = true;
    try {
      ... 提交 ...
    } catch (err) {
      ... 报错 ...
    } finally {
      btnSubmit.disabled = false;   // 无论成功还是失败，都会执行
    }

`finally` 的意思和 Python 里完全一样：**不管前面发生了什么，这里一定会执行。**

如果不写 `finally`，把 `disabled = false` 只放在成功分支里：
一旦提交失败（比如时间填错了），按钮就**永远卡在禁用状态**，
用户改完再点也没反应，只能刷新页面——体验极差。

**这个"按钮卡死"的 Bug 太常见了，用 `finally` 可以从根上避免。**

### 3.12 后端错误信息的中文化（`api.js`）

Pydantic 的报错是英文的：`Field required`、`String should have at most 200 characters`。
直接弹给用户看很不专业，所以在 `api.js` 里做了翻译：

    const MESSAGE_MAP = {
      'Field required': '必填项，不能为空',
      'Input should be a valid integer': '必须是整数',
      ...
    };

    // 长度类用正则提取数字："at most 200 characters" -> "长度不能超过 200 个字符"
    let m = msg.match(/at most (\d+) character/);

**为什么放在 `api.js` 而不是每个页面各写一遍？**
因为这属于"和后端打交道"的事。**统一在唯一出口处理，所有页面自动受益。**

## 六、常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 点"添加"后**页面刷新了**，什么都没发生 | 少写了 `event.preventDefault()` | 检查 `onSubmit` 第一行 |
| 提示 `field required` / 字段名对不上 | 前端 payload 的字段名和后端 `TaskCreate` 不一致 | 打开 F12 → Network → Payload 对照后端 `/docs` 的字段名 |
| 添加成功但**列表不刷新** | `loadTasks()` 没被调用，或抛异常被吞掉 | 看 F12 → Console 有没有红字 |
| 时间总是差一分钟 / 存进去多了 `:00` | 忘了 `.slice(0, 16)` | 见 3.9 |
| 标题里的 `<>` 显示不出来 / 页面错乱 | `escapeHtml` 被漏掉或写错 | 见 3.10 |
| 按钮点一次就**再也点不动**了 | 没写 `finally`，失败后 `disabled` 没恢复 | 见 3.11 |
| 访问 `/api/tasks/stats` 报错 | `/stats` 被写在了 `/{task_id}` 后面 | 见 3.6，静态路径要放前面 |
| `422` 但不知道哪错了 | 提示是英文的 | `api.js` 里已有翻译表；也可以看 Response 里的 `detail` |
| 中文提示变成乱码 | 命令行编码不是 UTF-8 | 双击 `start.bat`（内部已设 `chcp 65001`） |
