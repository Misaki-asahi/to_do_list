## 一、设计思路

### 1.1 打包最大的坑：程序装到哪、数据写到哪

源码运行时，一切都简单：**项目目录就是一切**。
但打包之后，"程序在哪"和"数据写哪"变成了两个完全不同的问题。

| 问题 | 源码运行 | 打包成 exe 后 |
| --- | --- | --- |
| 代码和资源在哪 | 项目目录 | **被塞进 exe / _internal 目录，只读** |
| 数据写在哪 | 项目目录下的 `data/` | **不能写旁边** —— 装在 `Program Files` 会直接被拒绝 |

**所以路径必须分成两类：**

```
只读资源（HTML / CSS / JS）  ->  跟着程序走
可写数据（数据库 / 备份）    ->  放到用户的 AppData 目录
```

> **这是所有 Windows 桌面程序的标准做法。**
> 一个"装完就写不了数据"的程序，是最常见的打包翻车方式。

### 1.2 装到哪？为什么不用 Program Files

| 位置 | 需要管理员权限 | 能写数据吗 | 结论 |
| --- | --- | --- | --- |
| `C:\Program Files\` | ✅ 需要 | ❌ 默认不可写 | 不选 |
| **`%LOCALAPPDATA%\Programs\`** | ❌ **不需要** | ✅ 可以 | ✅ **选它** |
| `%LOCALAPPDATA%\OfflineTodoList\`（数据） | ❌ | ✅ | ✅ 数据放这里 |

好处：**用户双击就能装，不需要管理员权限**，也不会 UAC 弹窗。

### 1.3 为什么自己写安装程序，而不是用 Inno Setup

Inno Setup 是 Windows 上最常用的安装包制作工具，但它有两个问题：

1. **它是第三方软件**，需要额外下载安装（官网给的是下载页面，自动化获取很麻烦）；
2. **这个项目一直坚持"依赖越少越好、别人 clone 下来就能用"**。

所以最后的做法是：**用 PyInstaller 把"安装程序"本身也打成一个 exe**。

```
第一层：build.bat            把程序打成 dist/OfflineTodoList/
第二层：build_installer.bat  把「程序目录」作为数据，塞进一个安装器 exe
                             产出 dist/OfflineTodoList-Setup.exe
```

**不引入任何新工具**，而且安装逻辑的代码就放在仓库里，你随时能看懂、能改。

```python
if FROZEN:

```

## 三、关键代码逐行解释

### 3.1 `getattr(sys, "frozen", False)` 是什么

PyInstaller 打包后，会在程序里注入一个 `sys.frozen = True`。
于是这一行就成了"我到底是不是打包版"的开关：

```python
FROZEN = getattr(sys, "frozen", False)
```

用 `getattr(..., False)` 而不是 `sys.frozen`，是因为**源码运行时这个属性根本不存在**，
直接访问会 `AttributeError`。给个默认值就两边都能跑。

### 3.2 `sys._MEIPASS` 是什么

PyInstaller 的 onefile 模式会把所有东西打包成一个 exe。
运行时，它先把内容解压到一个临时目录，再把 `sys._MEIPASS` 指向那里。

**所以打包后要找"随程序一起打包进来的资源"，就得用 `sys._MEIPASS`。**
用 `__file__` 是不行的 —— 它指向的是 exe 内部一个不存在的路径。

### 3.3 为什么打包后不能再用 `"app.main:app"` 这种字符串

```python
# 源码运行：能用
uvicorn.run("app.main:app", ...)

# 打包后：会找不到模块
```

原因：**PyInstaller 是靠"静态分析代码"来收集依赖的。**
它只会看你代码里写了哪些 `import` 语句 —— 
而 `"app.main:app"` 只是一个**字符串**，在它眼里就是普通文本，看不见里面的模块名。

结果：打包出来的 exe 里没有 `app.main`，运行时直接 ModuleNotFoundError。

**解决办法：把 app 对象直接传进去**，不经过字符串。
（代价是不能用 `reload=True` 热重载，但打包版本本来也不需要。）

这也解释了为什么打包命令里要加 `--hidden-import app.main` —— 
相当于手动告诉 PyInstaller："这个模块有人在用，别漏了"。

### 3.4 打包后没有控制台，`print()` 会出事

我们用 `--noconsole` 打包（不弹黑窗口）。
这种情况下 `sys.stdout` 可能是 `None`，**任何 `print()` 都会直接抛异常**，把程序搞崩。

处理方式（`run.py`）：

```python
def _ensure_std_streams():
    """打包成无控制台的 exe 后，stdout/stderr 可能是 None。"""
    if sys.stdout is None or sys.stderr is None:
        class _NullStream:
            def write(self, *_args): return 0
            def flush(self, *_args): pass
        if sys.stdout is None: sys.stdout = _NullStream()
        if sys.stderr is None: sys.stderr = _NullStream()
```

这样代码里所有的 `print()` 都能照常写。

### 3.5 启动失败要弹窗，不能只 print

```python
def show_error(message, title=None):
    try:
        import ctypes
        ctypes.windll.user32.MessageBoxW(0, str(message), str(title), 0x10)
    except Exception:
        print("[错误] %s" % message)
```

`ctypes` 是 Python 标准库，可以直接调用 Windows API，**不需要装任何东西**。
`MessageBoxW` 的最后一个参数 `0x10` 表示"红色错误图标"。

> **这是打包应用的一条铁律：没有控制台，就必须用弹窗告诉用户出了什么事。**
> 否则用户只会看到"双击了，没反应"。

### 3.6 「退出程序」按钮为什么必须要有

打包版**没有黑窗口**，用户点浏览器的 × **关不掉程序** ——
因为程序是一个独立的进程，浏览器只是它的一个"显示器"。

没有这个按钮，用户只能用任务管理器结束进程 —— 体验极差。

```python
@router.post("/shutdown")
def shutdown():
    def _exit_soon():
        time.sleep(0.8)              # 先让 HTTP 响应发回浏览器
        database.checkpoint_wal()    # 退出前把 WAL 合并回主库
        os._exit(0)
    threading.Thread(target=_exit_soon, daemon=True).start()
    return {"ok": True, "message": "程序即将退出"}
```

**为什么要延迟 0.8 秒？** 得先把响应发出去，页面才能显示"已退出"。
立刻 `os._exit()` 的话，浏览器只会看到一个连接中断的错误。

### 3.7 卸载程序里为什么有一段"复制自己到 TEMP"

```bat
if not "%~1"=="GO" (
    copy /y "%~f0" "%TEMP%\otl_uninstall.bat" >nul 2>nul
    start "" /min "%TEMP%\otl_uninstall.bat" GO
    exit /b 0
)
```

因为**正在运行的 .bat 文件没法可靠地删掉自己所在的目录**：

1. 卸载脚本住在 `%LOCALAPPDATA%\Programs\OfflineTodoList\` 里；
2. 它最后要执行 `rmdir /s /q` 把这个目录整个删掉；
3. 但它自己就在里面 —— 文件被占用，删不掉。

所以标准做法是：**把自己复制到临时目录，从那里重新启动一次**，
这样被删的目录里就没有正在运行的东西了。

### 3.8 卸载程序为什么用"按目标找快捷方式"而不是"按名字删"

```powershell
$sc = $ws.CreateShortcut($_.FullName)
if ($sc.TargetPath -like "*OfflineTodoList*") { Remove-Item $_.FullName -Force }
```

因为快捷方式的名字是**中文**（`离线待办清单.lnk`），
而卸载用的 `.bat` 文件必须是**纯 ASCII**（见 BUG-001），没法把中文写进去。

改成"遍历所有 .lnk，看它指向的目标是不是我们的 exe"，就绕开了这个问题 ——
**顺便还能清理掉用户改过名字的快捷方式**。

## 六、常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 双击 exe **没反应** | 端口被占用，或启动出错 | 用 `--console` 重新打包一次看报错；或先关掉旧窗口 |
| 提示"端口 8000 已被占用" | 之前有一个实例还在跑 | 任务管理器结束 `OfflineTodoList.exe` |
| 打包后**数据"丢了"** | 装了两个版本，各用各的数据目录 | 源码版在项目 `data/`，安装版在 `%LOCALAPPDATA%\OfflineTodoList\data\` |
| 打包后**页面打不开 / 样式丢失** | `--add-data` 漏了 static / templates | 确认命令里有两条 `--add-data` |
| `ModuleNotFoundError: app.main` | 打包时没加 `--hidden-import app.main` | 见 3.3 |
| 安装时提示**文件被占用** | 旧版本正在运行 | 安装程序会自动 `taskkill`，如果还不行就手动关掉 |
| 卸载后**快捷方式还在** | 快捷方式被改过名字，或指向了别的路径 | 手动删除即可（卸载程序是按"指向的目标"来找的，已覆盖大部分情况）|
| exe **体积很大**（32 MB）| Python 运行时 + FastAPI 全套都在里面 | 正常。已排除 tkinter / matplotlib / numpy 等无用模块 |

## 七、关于"32 位 / 64 位"

用户提到想打包成 **winx86**，这里说明一下：

| 问题 | 答案 |
| --- | --- |
| 现在打出来的是什么 | **64 位**（因为这台电脑装的是 64 位 Python）|
| 能不能打出 32 位 | **不能直接打** —— PyInstaller **不支持跨架构打包** |
| 要打 32 位怎么办 | 需要另外装一个 **32 位的 Python**，用它重新执行一遍打包 |
| 需要打 32 位吗 | **基本不需要** —— Windows 11 只有 64 位版本；64 位 exe 能跑在所有现代 Windows 上 |

> **结论：直接用 64 位就好。** 32 位 Windows 已经是极少数情况了。
